### 0.2 The multi-agent editing proposal, in one paragraph

The planner must give every write task a **declared write scope** (path globs) plus acceptance commands. The scheduler grants **leases** on those scopes in SQLite, so two tasks with overlapping write scopes never run at the same time: they get a dependency edge instead. Each write task runs in **its own git worktree on its own branch from one pinned base commit**. Agents never touch the user's checkout or main. When an agent says "done", soot itself:

1. snapshots the worktree diff;
2. **rejects edits outside the lease** and **edits to protected test files**;
3. runs the task's acceptance commands;
4. queues the branch for a **serial integration merge**, pre-checked with `git merge-tree --write-tree`, then re-runs validation on the integrated tree.

A task is `Verified` only when soot's own command results and the diff say so. The agent's message never counts. Context moves between models as a **structured TaskResult and findings ledger** (JSON Schema), never as a raw transcript. [Opinion; mechanisms Confirmed in §8]

### 0.3 Spec assumptions that vendors don't support (full list in §9)

The worst five [Confirmed]:

1. **Claude Code can't officially run non-Claude models.** Anthropic "doesn't support routing Claude Code to non-Claude models through any gateway."
2. **Cursor runs never use the user's own provider keys.** "All inference goes through Cursor's hosted models", billed to the Cursor plan.
3. **Only xAI and OpenRouter expose pricing through an API.** OpenAI, Anthropic, Google and DeepSeek list endpoints have no prices.
4. **Codex custom providers must speak the Responses API.** `wire_api = "chat"` isn't supported.
5. **MCP sampling is deprecated** (2026-07-28). An MCP server can't borrow the host's model, so soot's planner needs its own keys.

## 1. What the specs ask for, and Milestone 0 as written

- **Product** [Confirmed, build-spec §1–§20]: one prompt is decomposed into a task graph. The cheapest capable model is picked per task, with escalation and downgrade during the run. Tasks run in parallel, under isolation, with evidence-based validation and per-task cost. It installs as a skill, an extension, a CLI or MCP into existing harnesses. The suggested MVP is "TypeScript orchestration engine + LiteLLM + SQLite + Git worktrees + universal agent skill." Non-negotiables: BYOK, local-first, no lock-in, task-level billing, capability benchmarks, safe concurrency.
- **Milestone 0** [Confirmed, project-management §4]: repo initialized, monorepo, package manager, TypeScript config, lint and format, test framework, environment config, basic docs, CI, license. Exit: builds, tests run, CI passes, structure documented. The tracking files (PROJECT_STATUS, ROADMAP, TASKS, DECISIONS, TECHNICAL_DEBT, FUTURE_FEATURES, CHANGELOG) are part of §12's initial instructions.
- **What M0 needs from this research:** only toolchain-level decisions (§10). Everything else lands in M1–M5.

### 3.3 Ops cost of each option [Opinion unless tagged]

- **AI SDK in-process:** zero extra processes. npm supply-chain exposure is managed with pnpm 12's `minimumReleaseAge` and `trustPolicy` (both are settings in [pnpm settings](https://pnpm.io/settings)) [Confirmed setting names].
- **LiteLLM:** a Python 3 runtime or Docker. Postgres for keys and spend (proxy). Redis for multi-instance cooldowns. Pin exact versions, because `latest` Docker tags were the attack path on Oct 21 [Confirmed].
- **OpenRouter:** no ops, but fees plus a third-party data hop. This conflicts with "local-first" by default.

### 7.2 ACP is the adapter layer [Confirmed unless tagged]

- **Spec:** [agentclientprotocol.com](https://agentclientprotocol.com/overview/introduction.md), schema release `schema-v1.31.0` (Nov 10, 12:46 PM PT). - **Flow:** `initialize` → `session/new` or `session/load` (if `loadSession`) or `session/resume` (if `sessionCapabilities.resume`) → `session/prompt` → `session/update` stream → `session/request_permission` → `session/cancel` ([session setup](https://agentclientprotocol.com/protocol/v1/session-setup.md); [Cursor ACP](https://cursor.com/docs/cli/acp.md)).
- **Model selection:** a session config option with `category: "model"`. `model_config` was stabilized Jun 24, 2026 ([announcement](https://agentclientprotocol.com/announcements/model-config-category-stabilized.md); [config options](https://agentclientprotocol.com/protocol/v2/session-config-options.md)). - **Still an RFD, not stable:** "Configurable LLM Providers" (`providers/list|set|disable`) would let soot point an agent at its own gateway ([RFD](https://agentclientprotocol.com/rfds/custom-llm-endpoint.md)). Session fork is also an RFD. **Don't depend on either.** [Confirmed status as RFD; Opinion]
- **Permission requests** arrive as `session/request_permission`. "If your client does not answer permission requests, tool execution can block" ([Cursor ACP](https://cursor.com/docs/cli/acp.md)). soot must forward them to the user (the agent-pause design) and never auto-allow, per spec §13 [Confirmed; Opinion].

### 8.2 Proposed design [Opinion; each mechanism is a Confirmed primitive above]

1. **Plan with scopes.** Each task in the graph declares:
   - `write_scope` (globs);
   - `read_scope`;
   - `acceptance` (commands + expected results);
   - `protected` (paths it must not edit; default: test files unless the task is "write tests").

   The planner output is validated with JSON Schema. An unscoped write task is rejected back to the planner.

2. **Lease, don't lock.** A `lease` table in SQLite. Overlapping write scopes become a dependency edge, so they're serialized (NP-Bench-style proactive scheduling). Read-only tasks need no lease. Leases are released only at integration or cancel.
3. **One base commit, one worktree per write task:**
   - `git worktree add <soot-home>/wt/<run>/<task> -b soot/<run>/<task> <base_sha>`.
   - All tasks branch from the **same pinned base**, and dependents branch from their producer's integrated commit. This removes the "disjoint files but still conflict" base-mismatch class MergeGym measured.
   - Read-only tasks share one detached checkout.
4. **The harness runs inside the worktree** (ACP `cwd`, `claude -p` in cwd, `codex exec` in cwd, and so on). soot never passes `--worktree` to the harness, so soot alone owns worktree lifecycle and naming. The harness-native worktree flags differ per vendor (§7.1).
5. **Snapshot and scope-check on "done".** soot commits the worktree state itself and diffs it against `base_sha`:
   - edits outside `write_scope`: **reject → escalate**;
   - edits or deletions under `protected`: **reject** (ImpossibleBench);
   - an empty diff when the task expects changes: **not done**.
6. **soot runs acceptance itself:** the task's commands plus the repo's typecheck, lint and test where configured. It stores `evidence` rows (command, exit code, output hash, duration, sha). Agent self-reports are logged but never change status. This maps straight onto the mandatory Implemented ≠ Verified rule (project-management §6).
7. **Serial integration queue:**
   - Merge task branches in dependency order onto `soot/<run>/integration`.
   - Pre-check each with `git merge-tree --write-tree`.
   - A conflict means the task goes back with the conflict file list (CAID's "resolve locally and resubmit").
   - After each merge (or batch), re-run the affected validation. If the integrated tree fails, bisect over the merged task set.
   - The user's branch changes only after the user approves the final diff (spec §13).
8. **Context, not transcripts.**
   - Each attempt returns a typed `TaskResult`: `status`, `summary`, `files_changed`, `findings[]`, `open_questions[]`, `confidence`, `next_step`.
   - A run-wide `findings` ledger holds shared discoveries.
   - Escalation hands the next model this payload: the failed diff + ledger + acceptance results.
   - Harness `session_id`s are stored per attempt so the _same_ model can resume. A _different_ model always starts a fresh session with the payload, because reasoning traces aren't portable (§3.2).
9. **Shared non-git resources.** Worktrees don't isolate ports, local databases, caches, `node_modules` or `.env`.
   - Per-worktree setup hooks (as in Cursor's `worktrees.json` and Kilo's setup scripts).
   - A port allocator.
   - **Never auto-copy `.env` into agent worktrees.** Cursor's own example does `cp $ROOT_WORKTREE_PATH/.env .env` ([worktrees](https://cursor.com/docs/configuration/worktrees.md)), which conflicts with spec §9/§13 secret isolation. Use an explicit allowlist [Confirmed example; Opinion].
10. **Cleanup:** prune worktrees on run end, and keep failed ones for inspection with a TTL (Grok Build leaves worktrees "until you remove them", which is a reminder to prune). [Confirmed; Opinion]

### 8.3 Failure modes and the guard for each

| Failure                                                                     | Guard                                                                                                                                                                                       |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Two agents write the same file                                              | Lease conflict → serialized; worktrees mean a lost write can't even happen; merge-tree pre-check                                                                                            |
| Disjoint files but a semantic or contract break                             | Producer→consumer ordering, integrated-tree validation, bisect                                                                                                                              |
| Agent says "done", but tests never ran                                      | soot runs acceptance itself; status comes from `evidence` only                                                                                                                              |
| Agent "fixes" tests by deleting or weakening them                           | `protected` paths plus a diff check; tests may be edited only by test-scoped tasks; an optional reviewer task on a _different_ model when the diff touches tests                            |
| Context overflow / lost thread                                              | Small task-specific context; structured `TaskResult`; findings ledger; harness compaction is the harness's own business                                                                     |
| Lost state after a crash                                                    | SQLite is the source of truth; on restart, worktrees are re-attached from rows, harness sessions resumed by stored id, and unfinished attempts marked `interrupted` and re-queued (bounded) |
| Escalation loops                                                            | `attempt` count and budget per task (spec §6)                                                                                                                                               |
| Provider 429 / spend caps (Gemini $10/10 min, DeepSeek account concurrency) | Per-provider concurrency semaphore + cooldown table + fallback candidate list                                                                                                               |
| Headless run blocks on approval (Cursor rejects; ACP blocks)                | Surface it as a pause via the agent-pause design; never `--force`/`--always-approve` by default                                                                                             |

### 8.4 Rejected alternatives

| Alternative                                                          | Why not                                                                                                                                                |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Shared workspace + file locks                                        | Vendors themselves warn about overwrites (Claude teams, Kilo subagents). No harness exposes a lock API to an outside orchestrator [Confirmed; Opinion] |
| CRDT live co-editing                                                 | Semantic conflicts and mixed speed in the paper's own numbers; no harness supports it [Confirmed]                                                      |
| Patch-only, no worktrees (agents return diffs and soot applies them) | Fine for tiny API-executor tasks, but tool-using agents need a real checkout to run tests. Keep it as a mode, not the default [Opinion]                |
| Container per agent from day one                                     | Docker dependency, slower; container-use is "experimental". Add later as an optional tier [Confirmed; Opinion]                                         |
| LSP- or AST-level locks                                              | No harness integration point; over-engineered for MVP [Opinion]                                                                                        |
| Each harness's own worktree flag                                     | Four different layouts and cleanup rules; soot loses control of naming and base commit [Confirmed layouts; Opinion]                                    |

## 10. What should change for Milestone 0 right now

**Verdict: Milestone 0 can proceed as written.** Record these in DECISIONS.md, because each is a fork in the toolchain that's cheap now and costly later. [Opinion; versions Confirmed via npm, nodejs.org and pnpm.io today]

1. **TypeScript version vs linter.**
   - Latest is TypeScript **7.0.2**, and **`typescript-eslint` 8.72.2 peers `typescript >=4.8.4 <6.1.0`**, so the two don't work together today.
   - Pick one: **(a)** TS **6.0.3** + typescript-eslint (type-aware lint), or **(b)** TS 7 + Biome 2.6.7 or oxlint 1.93.0 (faster, less type-aware).
   - `tsdown` 0.23.7 accepts TS 5, 6 or 7.
   - I lean (a) for M0, because strict typing is a spec requirement and type-aware lint helps [Opinion].
2. **Runtime and package manager.**
   - Pin Node **26 LTS** ("Lithium", v26.13.1 released Nov 10) in `engines` and CI. Vitest 5.1.0 requires `^22.12 || ^24 || >=26`.
   - pnpm **12.18.0**. Turn on `minimumReleaseAge`, `trustPolicy` and `strictDepBuilds` (all listed in [pnpm settings](https://pnpm.io/settings)). This is the npm answer to the class of attack that hit LiteLLM twice.
3. **No Python in M0.** Don't add LiteLLM to the toolchain. Leave a `providers` package boundary so a LiteLLM endpoint is just another OpenAI-compatible base URL later.
4. **SQLite driver.** `node:sqlite` (RC in Node 26, no native build) vs `better-sqlite3` 13.1.1 (native build, needs a pnpm build allowance). I lean `node:sqlite` [Opinion].
5. **License and proprietary SDKs.**
   - **MIT** (closed by Mochi, 2026-11-12 1:00 AM PT: already committed). Apache-licensed dependencies (AI SDK, ACP, and others) are fine to use from an MIT repo.
   - `@anthropic-ai/claude-agent-sdk` and `@cursor/sdk` are **proprietary**. They must be optional peer dependencies of adapter packages, never bundled or vendored.

**Smaller M0 notes [Opinion]:**

- **Fewer packages to start.** The spec lists 12 packages plus 4 extensions. For M0, consider `core` (task graph, state, scheduler), `providers`, `registry`, `harness-acp`, `cli`, and add the rest when there's code. That's consistent with "Avoid unnecessary abstractions" (build-spec §19).
- **CI with two lanes:**
  - an offline lane (mocked providers, fixture repos for worktree and merge tests; this runs on every PR);
  - a manual real-provider lane that never runs on fork PRs.
- **Secret scanning** in CI and a committed `.env.example` only (spec §18: "Never commit real API keys").
- **Fixture git repos for tests** go in `tests/fixtures`, so M5 conflict tests can start early.

## 11. Risks, dependencies, and closed decisions

**Technical risks [Opinion unless tagged]:**

1. **Supply chain.** soot holds every provider key locally. LiteLLM (Mar and Oct 2026) and the npm CanisterWorm campaign named in [Datadog's write-up](https://securitylabs.datadoghq.com/articles/litellm-compromised-pypi-teampcp-supply-chain-campaign/) [Secondary] show this is real. Mitigate with pinning, release-age gating, a minimal dependency tree, and keys read only by the provider layer (never put in task context, per spec §9).
2. **Harness churn.** Flags are moving monthly. Codex removed `--full-auto` and `mcp-server`; Kilo deprecated Orchestrator; VS Code is deprecating its Local harness; Windsurf became Devin [Confirmed]. Mitigate with ACP first and contract tests per adapter.
3. **Planner quality is the product.** Bad scopes or acceptance criteria make every downstream guard noisy. Budget M1 time for planner evals on fixture prompts (spec acceptance tests 1–4).
4. **Savings claims.** FrugalGPT reports "up to 98% cost reduction" and RouteLLM "over 2 times" in _their_ settings ([2305.05176](https://arxiv.org/abs/2305.05176), [2406.18665](https://arxiv.org/abs/2406.18665)) [Confirmed]. soot must measure its own (spec §12 already says so).
5. **Rate and spend caps under fan-out:** Gemini spend limits, DeepSeek account concurrency, Anthropic 429s without `retry-after` [Confirmed].
6. **Worktree disk and time cost.** Each write task needs a dependency install in its worktree. Large monorepos may need a shared package store or a copy-on-write strategy [Speculation].
7. **ACP agents differ in capability.** Check `loadSession`, `resume` and the model option per agent at `initialize` and degrade gracefully [Confirmed: capabilities are optional].

**Dependencies:**

- AI SDK, the ACP TS SDK (peer `@modelcontextprotocol/server ^2.4.0`, which needs zod 4, per our Nov 11 findings), git ≥2.38 for `merge-tree --write-tree` [Speculation on the exact minimum version; git-scm documents the modern mode], and Node 26.
- Optionally: claude-agent-acp, codex-acp, harness CLIs installed by the user.

**Closed decisions** (Mochi, 2026-11-12 1:00 AM PT, so Sweed and Lumen are not blocked; do not ask Joseph. Treat as closed unless new evidence changes one of them):

1. **License:** MIT. Apache-licensed dependencies are fine to use from an MIT repo. Proprietary SDKs stay optional peer dependencies of adapter packages, never bundled.
2. **Subscription CLIs:** yes, soot may launch the user's own already-installed, already-signed-in CLIs (`claude`, `codex`, and similar) on their machine. That is the existing-workflow path. Constraints: only the user's local install and existing login; never offer login or rate limits for them; never bundle or vendor proprietary Agent SDKs; never bypass the host's approval settings; never brand soot as Claude Code or another vendor's product. If a vendor's terms later forbid a specific adapter, disable that adapter.
3. **DeepSeek:** leave it out of the default MVP path and out of any demo that would send code to their API, until Joseph reviews the data-residency policy. The registry can still know the models exist.
4. **First two MVP providers:** Anthropic and OpenAI. Implement them behind the abstraction with mocks. No real paid calls and no spending until Joseph provides bring-your-own keys.
5. **Approvals:** never auto-approve. If a headless run hits an approval prompt, pause and wait when a user can approve. If the run is unattended and no approval can be collected, refuse that task. Other independent tasks can continue.
6. **Minimal soot-owned API executor:** yes, for trivial, tightly scoped tasks only. The model returns structured edits; soot applies them in the worktree under the same leases, worktrees, and evidence tests. It is not a competing coding assistant: no general shell, tight file allowlist, no feature-creep into a full harness.

**Architecture accepted** (same message): Vercel AI SDK in-process (LiteLLM is an optional endpoint only, not a required dependency); thin model registry; SQLite task state machine; ACP for harnesses; write-scope leases plus one worktree per write task plus soot-run tests plus a serial merge queue. Do not adopt the experimental AI SDK harness packages for M1–M5.
